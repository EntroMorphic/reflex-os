## 2. Confirmed Defects

Ranked by severity × reachability.

### D1 — Warm boot silently disables metabolic regulation and kills the LED service

**Files:** `goose_runtime.c:314-326`, `goose_metabolic.c:117-152`, `services/led_service.c:29-36`,
`services/temp_service.c:48`

`goose_fabric_alloc_cell` returns **NULL** when the coordinate is already occupied:

```c
if (goose_fabric_get_cell_by_coord(coord) != NULL) {
    reflex_critical_exit(&fabric_mux);
    if (name) goonies_register(name, coord, is_system_weaving);  /* name re-registered... */
    goose_loom_unlock();
    return NULL;                                                  /* ...but caller gets NULL */
}
```

`fabric_cells[]` is `REFLEX_RTC_DATA_ATTR` — it survives deep sleep. On wake,
`goose_fabric_init` takes the warm-boot branch and every seeded coordinate is still occupied,
so every caller that *captures* the return value gets NULL:

| Caller | Consequence on warm boot |
|---|---|
| `goose_metabolic_init` (4 cells) | `s_batt/mesh/heap/metabolic` all NULL → `goose_metabolic_sync` falls through to its literal defaults `(0, 1, 0, 1)` → `compute_circuit_breaker` always returns **+1 thriving**. The circuit breaker can never trip again, so weave / explore / learn / swarm / snapshot gating in `goose_supervisor_pulse` all become unconditional. |
| `services/led_service.c:31` | `!led_phys` → logs "Failed to manifest LED in Fabric!" and calls `reflex_task_delete(NULL)` — **the LED service permanently exits**. |
| `services/temp_service.c:48` | `s_temp_cell` NULL → guarded, no crash, but the temperature vital freezes forever. |

The comment at `goose_runtime.c:316-322` shows the author already reasoned about warm-boot
semantics here and fixed the *name registry* half. The *return value* half was missed.

**Severity: HIGH.** Live, user-visible, silent. `bonsai sleep` (`shell.c:784`) reaches it.
**Confidence: HIGH.**

**Fix direction:** return the existing cell rather than NULL (the caller's intent is
"ensure this cell exists"), or have callers fall back to `goonies_resolve_cell(name)`.
Returning the existing cell is the smaller change and matches every call site's expectation.

### D2 — NULL dereference in the supervisor's 10 Hz equilibrium check

**File:** `goose_supervisor.c:232-234`

```c
if (r->cached_source && r->cached_source->type == GOOSE_CELL_HARDWARE_IN) continue;
reflex_trit_t orient = ...;
reflex_trit_t expected = (reflex_trit_t)((int)r->cached_source->state * (int)orient);
```

When `cached_source` is NULL the `&&` short-circuits, the `continue` is **not** taken, and
line 234 dereferences NULL unconditionally.

`cached_source` is genuinely nullable, and the codebase knows it — `goose_runtime.c:663-669`
re-resolves it and then guards `if (!r->cached_source || !r->cached_sink) continue;`, and
`goose_supervisor_evaluate:304` guards identically. Round-robin eviction of unpinned cells
(`goose_runtime.c:331-350`) is the mechanism that makes a previously-valid source vanish.

A second, related defect at the same site: `check_equilibrium` never validates
`cached_version` against `fabric_version`, unlike `internal_process_transitions`, which does.
After an eviction recycles a slot, the supervisor reads a stale pointer into a *different*
cell's data.

**Severity: HIGH.** Runs at 10 Hz on every supervised field. **Confidence: HIGH.**

### D3 — Bootloader "software reset to retry" writes the wrong bit and hangs

**File:** `bootloader_components/main/reflex_boot0.c:369`

```c
while (1) { REG_WRITE(0x600B1034, 0x8000); } /* LP_WDT_SWD_WPROTECT + force reset */
```

Verified against the C6 SoC headers:

- `0x600B1034` is **`LP_AON_SYS_CFG_REG`** (`DR_REG_LP_AON_BASE` = `0x600B1000`, + `0x34`).
  The comment naming LP_WDT is wrong — `LP_WDT_SWD_WPROTECT_REG` is `0x600B1C20`.
- That register defines exactly two bits: `LP_AON_FORCE_DOWNLOAD_BOOT` (BIT 30) and
  `LP_AON_HPSYS_SW_RESET` (BIT 31).
- The code writes `0x8000` — **bit 15, which is reserved**. The intended value is
  `0x80000000` (`LP_AON_HPSYS_SW_RESET`).

The reset never fires. A board that reaches the "no factory partition" path spins in a tight
register-write loop **forever** instead of resetting to retry, with no further output.

**Severity: HIGH** (unrecoverable hang), **error path only**. **Confidence: HIGH** — the
register semantics are unambiguous.

### D4 — Bootloader loads image segments with no bounds check and no integrity check

**File:** `reflex_boot0.c:302-306`, `:273-339`

```c
if (is_sram_addr(seg.load_addr) || is_rtc_addr(seg.load_addr)) {
    if (flash_read(flash_offset, (void *)seg.load_addr, seg.data_len) != 0) { ... }
}
```

`is_sram_addr` validates only the **start** address. `seg.data_len` is unbounded, so a
segment whose `load_addr` sits near the end of the window writes past it — SRAM is
`0x40800000–0x40880000`, RTC is only `0x50000000–0x50002000` (8 KB). The overflow lands on
the bootloader's own stack and code.

Compounding it: **there is no image verification of any kind.** `reflex_image_header_t`
declares `hash_appended`, and it is parsed and then never used. No SHA-256, no CRC, no
signature. This replaces the ESP-IDF bootloader, which *does* verify the image hash — so it
is a capability regression, and neither `SECURITY.md` (which never mentions boot0) nor the
"Known Gaps" section of `implementation-status.md` records it.

That documentation omission is itself the finding worth acting on: the project's own
same-commit doc-sync discipline was not applied to the most security-sensitive code in the tree.

**Severity: HIGH.** Executes on every boot. **Confidence: HIGH.**

### D5 — Metabolic heap gauge queries the wrong capability mask

**File:** `goose_metabolic.c:52-58`

```c
extern uint32_t heap_caps_get_free_size(uint32_t caps);
uint32_t free_bytes = heap_caps_get_free_size(0);  /* MALLOC_CAP_DEFAULT = 0 on some configs */
```

The comment is factually wrong: `MALLOC_CAP_DEFAULT` is `(1<<12)` (`esp_heap_caps.h:41`),
never 0. Passing `0` means "no capability required", which sums **all** heap regions —
including DMA-only and RTC memory that `malloc()` cannot serve.

So `perception.heap.pressure` over-reports free memory, and the circuit breaker reads
"comfortable" while malloc-able heap is actually tight. That defeats the purpose of the
vital, and `goose_fabric_alloc_cell:299-302` uses exactly this cell to refuse non-system
allocations under pressure.

Secondary: the prototype is hand-declared rather than taking `#include "esp_heap_caps.h"`.
The real return type is `size_t` — identical on 32-bit, but it bypasses header type-checking
and breaks a 64-bit host build.

**Severity: MEDIUM.** Live, on the supervisor sub-pass. **Confidence: HIGH.**

### D6 — Autonomous exploration reads arbitrary MMIO with no sanctuary check

**File:** `goose_supervisor.c:647-649`, `:689-691`

```c
volatile uint32_t *reg = (volatile uint32_t *)entry->addr;
uint32_t now = *reg;
```

`goose_supervisor_explore` walks the shadow atlas and **reads raw hardware registers** —
up to 8 probes per second, each read twice — filtered only on `type == GOOSE_CELL_HARDWARE_IN`
and `bit_mask == 0xFFFFFFFF`.

`is_sanctuary_address` has exactly one call site: `goose_fabric_set_agency`
(`goose_runtime.c:368`). So the guard covers *binding* a cell to an address but **not
probing** it. By the time a sanctuary address is rejected at bind time, it has already been
read twice.

This matters because MMIO reads are not side-effect-free: read-to-clear interrupt status
registers, RX FIFOs, and similar registers belonging to *live* peripherals can be disturbed
by an autonomous prober. The feature is gated on purpose being set and `metabolic >= 0` —
and per D1, after a warm boot `metabolic` is pinned to +1, so the gate is always open.

**Severity: MEDIUM-HIGH** (design hazard rather than a crash). **Confidence: HIGH** that the
guard is absent; **MEDIUM** on real-world impact, which depends on which registers the SVD
marks readable.

### D7 — Mesh-health vital ignores QUERY traffic

**File:** `goose_metabolic.c:66-67`

The sum is `rx_sync + rx_discover + rx_advertise + rx_posture + rx_mmio_sync`.
`mesh_stats.rx_query` (`goose_atmosphere.c:266`) is omitted, though `rx_discover` (line 312)
is included. A board receiving only QUERY arcs is judged idle, `s_mesh_idle_ticks` climbs,
and the mesh vital reports −1 (isolated) — which then *doubles* discovery frequency via the
inverted governance at `goose_supervisor.c:817`.

**Severity: LOW-MEDIUM.** **Confidence: HIGH.**

### D8 — `goose_weave_loom`: unvalidated indices, unbounded reads, one-way quota

**File:** `goose_library.c:95-149`

This is the bug flagged as §5d in the April audit. It was **not fixed**, and reading it
closely shows it is worse than reported:

- `routes[i].src_idx` / `snk_idx` are **`uint16_t`** (`goose.h:308-313`) and are never
  bounds-checked against `head->cell_count` (capped at 64). `resolved_cells[src_idx]` reads
  up to 65,535 slots past a 64-entry VLA and then dereferences the result.
- `resolved_cells[i]` comes from `goonies_resolve_cell`, which returns NULL on failure, and
  is dereferenced at line 137-138 with no NULL check — the originally-reported bug.
- `size` is checked only against `sizeof(loom_header_t)`. The cell and route arrays are then
  read from the buffer without verifying `size` covers them.
- `active_loom_fragments++` (line 114) is never decremented and no unweave function exists,
  despite the "Unweave Fragment" doc comment at 87-90. The quota is a one-way ratchet: after
  8 weaves the feature is dead until reboot.

**Reachability: `goose_weave_loom` has zero callers, and the linker garbage-collects it —
the symbol is absent from `reflex_os.elf`.** It ships in no image.

**Severity: LOW today, HIGH the moment it is wired up** — and `docs/prd-tasm-upload.md` plans
exactly that. `tools/loomc.py` already emits the format. Fix it before, not after.
**Confidence: HIGH.**

### D9 — Cooperative scheduler is structurally broken (ships in no image)

**File:** `kernel/reflex_sched.c`

- `reflex_sched_delay_ms:128-135` sets `state = BLOCKED`, then calls `reflex_sched_yield`,
  whose save path is guarded by `if (s_current->state == RUNNING)` (line 116) — now false.
  **`setjmp` is skipped and the context is never saved.** On resume the scheduler does
  `longjmp(next->context, 1)` (line 237) into a zero-initialised `jmp_buf`.
- `:227-231` switches stacks with `__asm__ volatile ("mv sp, %0")` mid-function while the
  compiler still believes it owns the frame. `next` and `new_sp` may live in the old frame,
  and `next->state` is written after `entry()` returns through a possibly-clobbered pointer.
  This works only by optimisation-level luck.

**Reachability: `reflex_sched.c` compiles, but the linker GCs it entirely — no `reflex_sched_*`
symbol appears in `reflex_os.elf`.** Only `reflex_task_kernel.c`, `reflex_portasm.S`, and
`reflex_freertos_compat.c` link in from `kernel/`, consistent with `implementation-status.md:189`.

The trap is that `sdkconfig.defaults:13` sets `CONFIG_REFLEX_KERNEL_SCHEDULER=y`, which reads
as though this scheduler were live. It is not.

**Severity: LOW today, HIGH if revived.** **Confidence: HIGH.**

## 3. Checked and Cleared

Recording these so the next audit does not re-litigate them:

- **Atmosphere receive ordering is correct.** `atmosphere_recv_cb` runs length check →
  self-drop → version gate → **Aura verify** → replay cache → op dispatch. `goose_mmio_sync_recv`
  is fully authenticated, so its auto-peer-add and NVS write cannot be driven by an unauthenticated
  attacker.
- **No unsafe string functions anywhere** in hand-written source — zero `strcpy`, `strcat`,
  `sprintf`, `gets`. Consistently `strncpy`/`snprintf` with explicit sizes. This is unusual
  discipline for an embedded C tree of this size and deserves saying.
- **`core/fabric.c:39`** bounds-checks `msg->to < REFLEX_NODE_MAX` before indexing. Not a bug.
- **`goose_metabolic` unsigned `delta` wrap** — no stats-reset path exists, counters are
  monotonic, uint32 wrap is theoretical. Not a bug.
- **`reflex_sched.c` stack-top arithmetic** — `stack_base + stack_size/sizeof(uint32_t)` is
  correct given `uint32_t*` scaling.
- **`goose_mmio_sync` NVS load** — `count` is clamped to `MAX_PEERS` before sizing the read.
- **Snapshot load bounds** — `goose_snapshot_load:521` guards `pos + SNAP_ROUTE_ENTRY_SIZE <= len`,
  so the header/payload count mismatch for fields with >16 routes truncates silently but
  cannot overflow.

## 5. What Is Strong

Assessment carried forward from April holds — the SVD-to-semantic-name pipeline, the two-tier
paged naming service, distributed hardware DNS over ESP-NOW, and the purpose-modulated routing
loop remain the real contribution. New since then and genuinely good:

- **The metabolic design.** Instant degradation, hysteretic recovery, and the deliberate
  exclusion of `mesh` from the circuit breaker (`goose_metabolic.c:83-85`) with the reasoning
  recorded in-line. The supervisor's gating table — what suspends in *surviving*, what halves
  in *conserving*, what always runs for safety — is a legible resource-governance policy, not
  ad-hoc throttling.
- **Deferred telemetry under lock.** `goose_supervisor_learn_sync:360-364` snapshots route
  state inside `loom_authority` and emits outside it. Correct instinct, correctly executed.
- **Boot-loop protection in boot0** is real: a magic-tagged LP_AON counter, checked before
  load and cleared only on success. The mechanism is sound; only the reset write (D3) is wrong.
- **The self-owned bootloader is a genuine milestone.** Partition reader, image loader, MMU
  mapper, and cache init written against ROM and SoC headers only, with the dependency
  boundary documented at the top of the file. D3/D4 are correctable defects in real work, not
  evidence the effort was misguided.
- **Zero-warning build** at 18% partition headroom.

## 6. Structural Health

Unchanged from April: module boundaries are clean, dependency direction is enforced, headers
are well-documented.

Deteriorating:

- `goose_runtime.c` (778) and `shell.c` (1,177) both grew after being flagged. `shell.c` is
  now the second-largest hand-written file in the tree.
- **18% app-partition headroom** is the constraint to watch. It is comfortable now and will
  not stay comfortable.
- `bonsai/` + `journal/` = 90 files of archival prose still sitting at the root, referenced
  only by `README.md` and two planning docs.

New concern — **dead code is accumulating faster than it is being removed.** Three separate
subsystems are compiled but reach no image (`reflex_sched.c`, `goose_weave_loom`) or run
against a queue nobody writes (`goose_gateway`). Each carries real defects (D8, D9). The risk
is not wasted flash; it is that a future contributor wires one up and inherits its bugs.
`CONFIG_REFLEX_KERNEL_SCHEDULER=y` sitting in `sdkconfig.defaults` while the scheduler is
linker-stripped is precisely that trap.

## 7. Documentation Drift

Per the project's own same-commit doc-sync rule, these are gaps rather than opinions:

1. **`SECURITY.md` never mentions boot0.** The custom second-stage bootloader performs no
   image verification, replacing one that did. This belongs in SECURITY.md §, and in
   "Known Gaps".
2. **"Known Gaps" is stale.** It still frames the remaining limits as of the April sweep and
   has no entry for the bootloader, the exploration prober's unguarded MMIO reads, or the
   linker-stripped kernel scheduler.
3. **`CONFIG_REFLEX_KERNEL_SCHEDULER=y`** advertises a scheduler that ships in no image.
4. **Supervisor sub-pass rates are ~9% slow.** Every divider uses `if (div++ >= N)`, which
   fires on the *(N+1)*-th pulse. With `N = 10` at 10 Hz, the documented "1 Hz" sub-passes
   actually run at ~0.909 Hz. Harmless, but the docs state 1 Hz.
5. **Snapshot format comment** (`goose_supervisor.c:426-433`) omits the `version` field that
   `SNAP_HEADER_SIZE = 4` actually reserves, and does not mention the silent 16-route truncation.

## 8. Verdict

The load-bearing work is still strong, and the April remediation was done honestly — the
scaffolds that claimed functionality they lacked were reduced to stubs rather than papered
over, and the host test gap was genuinely closed.

The defects found here cluster in **new code that has not yet met hardware in its failure
modes**. D1 is the one to fix first: it is silent, it is triggered by a shipped shell command,
and it disables the entire metabolic safety layer while leaving every status readout claiming
"thriving". D2 and D3 are crashes and hangs — worse in the moment, but loud. D4 is the one
with the widest blast radius if an image is ever corrupted, and it is also the clearest
documentation failure.

The structural risk has shifted since April. It is no longer that a reader meets the journals
before the real work; `lmm_repo/` is gone and the docs have matured considerably. It is that
**three dead subsystems carrying nine defects between them are one commit away from being
reachable**, and nothing in the tree marks them as inert.

Recommended order: **D1 → D2 → D3 → D4 → D5 → D6 → D7**, then either delete or explicitly
quarantine `goose_weave_loom`, `reflex_sched.c`, and `goose_gateway.c` before the TASM-upload
PRD lands.
