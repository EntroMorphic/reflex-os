# Cortex-M Port — Scope

**Status:** Scoping. **First target:** STM32L4A6 (Nucleo-L4A6ZG) — the board we've already brought up
bare-metal for the TSLE detector. **Why:** the first **non-Espressif** target turns "multi-architecture
behind a HAL" into the real **without-walls** portability proof, and the M4**F** has an FPU (the ESP32-C6
doesn't), so it's the easiest place to land both the substrate and the Sentinel sense.

**Head start (already built, in `~/Projects/tsle/standalone/nucleo/`):** Cortex-M4 startup + vector table,
linker script, FPU enable, GPIO (LED), LPUART VCP @9600, `arm-none-eabi` toolchain, and a working detector
on-chip. Bucket 2 is partly done; the bootloader story is *simpler* than ESP (ROM bootloader + our vector
table at `0x08000000`, no custom Boot0).

The mantra from the analysis: the registers aren't the gating question — **the mesh transport is.**

---

## Bucket 1 — SVD-regen (the MMIO atlas)  · *tractable, mostly mechanical*
The atlas is generated by `tools/goose_scraper.py(svd_path, zones_path, output_path)` — path-parameterized,
not hardcoded. The "completely different" STM32 register surface is absorbed by pointing it at a different SVD.
- **Source** the STM32L4A6 CMSIS-SVD (ST publishes it; also in `cmsis-svd` repos / STM32CubeL4).
- **Define a zones file** — the priority peripherals to pre-weave (RCC, GPIO, USART/LPUART, TIM, ADC, PWR, …),
  analogous to the C6's 104 pre-woven cells.
- **Generate** `goose_shadow_atlas_stm32l4a6.c`. The `goonies` names (`peripheral.register`) fall out of the SVD
  automatically — naming ports for free.
- **Validate** with `atlas verify` (round-trip read + duplicate sweep); confirm node count.
- **Risk:** ST SVD quirks (register clusters, `derivedFrom`, array expansion) may need scraper tweaks.
- **Effort:** LOW–MEDIUM.

## Bucket 2 — Drivers (`platform/cortexm` HAL backend)  · *the bulk; partly built*
Mirror `platform/esp32c6/*` with a new `platform/cortexm` (or `platform/stm32l4`):
- **`reflex_hal_cortexm.c`** — GPIO/LED, 1 Hz policy tick (SysTick or a TIM), die-temp (ADC), deep sleep
  (STM32 STOP/STANDBY), warm reset. **Reuse the Nucleo GPIO + LPUART + startup/linker + FPU-enable verbatim.**
- **Scheduling HAL** — the HAL already abstracts "FreeRTOS or `reflex_task_kernel`." **Decision:** FreeRTOS-ARM
  (mature Cortex-M port, fastest path to a shell, supplies PendSV/SVC port asm) vs the bare `reflex_task_kernel`
  (purer/blob-free, but you must port the kernel's interrupt-context ownership — the `--wrap rtos_int_enter/exit`
  + `reflex_portasm.S` mechanism — to the ARM NVIC/PendSV model). *Recommend FreeRTOS-ARM for v1, revisit bare for
  the blob-free story.*
- **`reflex_kv_cortexm.c`** — persistent KV on internal flash (sector erase/program with wear-leveling, or
  emulated-EEPROM), replacing ESP NVS. Needed for snapshots / Sentinel model persistence.
- **`reflex_crypto_cortexm.c`** — HMAC-SHA256 (software SHA256, or the STM32L4 hash accelerator). **Only needed
  when mesh lands** — stub for the single-node v1.
- **Effort:** MEDIUM–HIGH (the real coding), head-started by the Nucleo bring-up.
- **Decisions:** scheduler (above); minimal first peripheral set = LED + UART shell + tick + temp + KV.

## Bucket 3 — Radio-transport (the mesh PHY)  · *the actual gating decision*
The STM32L4A6 has **no integrated radio**; the entire mesh/hive (atmospheric discovery, postural arcing,
`ARC_OP_*`, MMIO sync, Aura HMAC) rides the C6's 802.15.4. Options:
- **(a) Skip mesh for v1** — single-node OS only. Add a `RADIO_BACKEND=none` (the backend is already Kconfig-gated
  IEEE802154 vs ESP-NOW); the mesh layer compiles out. **Fastest; proves the substrate ports. [recommended for v1]**
- **(b) External 802.15.4** transceiver over SPI → a `reflex_radio_spi` backend. Keeps mesh; adds HW + a driver.
- **(c) ARC-over-wire** (UART/CAN) — the ARC protocol is packet-based and transport-agnostic; a wired bench-mesh.
- **(d) Radio-bearing STM32** — STM32**WB** (BLE + 802.15.4) or STM32**WL** (sub-GHz). Native radio, mesh ports
  most directly; this is a deliberate **hardware/board** decision, not a code one.
- **Effort:** (a) LOW · (b)/(c) MEDIUM–HIGH · (d) board change.
- **Recommend:** (a) for the first port; choose the wireless target (WB/WL) deliberately when the mesh is the goal.

## Sequencing
- **P0** Generalize the Nucleo bring-up into `platform/cortexm` (startup/linker/clock/FPU). *(mostly done)*
- **P1** SVD-regen the STM32L4A6 atlas; pass `atlas verify`.
- **P2** HAL: scheduler + LED + UART shell + 1 Hz tick + KV-flash → **boot to the reflex shell on the M4F.**
- **P3** Substrate + perception + metabolic on the new atlas — these are architecture-independent C; they should
  compile once the HAL + atlas exist (this is the test of whether the abstraction is real).
- **P4** Sentinel sense (fixed-point per [`sentinel.md`](sentinel.md) v2) on a real M4 signal.
- **P5** *(deferred)* radio/mesh transport decision (b/c/d).

| bucket | effort | status |

| 1 — SVD-regen atlas | low–medium | mechanical; scraper reusable |

## What it proves
P2–P4 alone (boot the substrate + perception + metabolic + Sentinel on the M4F, no mesh) is the
**"without walls" credibility milestone** — reflex-os running on a non-Espressif chip, the ecosystem's
portability claim made real, and reflex-os + the TSLE Sentinel on the same silicon we've already lit up.

## Risks
SVD quirks (Bucket 1); the interrupt-context port if going bare-kernel (Bucket 2); FreeRTOS-vs-bare decision;
KV-flash wear; software-crypto cost when mesh lands. None are blockers; the only true fork is the mesh transport.
