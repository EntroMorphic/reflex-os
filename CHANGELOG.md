# Changelog

All notable changes to Reflex OS are documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.1.0/)
and this project uses a loose form of [Semantic Versioning](https://semver.org/spec/v2.0.0/).

## [Unreleased]

### Added

- **Documentation gap sweep** — `docs/USER_MANUAL.md` was missing three registered commands (`kernel`, `loom`, `tapestry`) and had no coverage of the input rules or the `#R:` outcome marker; all are now documented, along with a warning that `vm run` blocks the shell. Public header contracts that names cannot convey are now written down: `reflex_kv` handle lifecycle, in/out `len`, and that `commit` is a no-op on the flash backend but required for portability; `reflex_radio_send` returning OK for *queued*, not delivered; `reflex_hal_gpio_get_level` returning 0 for an out-of-range pin, indistinguishable from a genuine low; and `reflex_hal_sleep_enter` never returning. Undocumented public declarations went from 32 to 23, the remainder being accessors covered by their group contract rather than worth restating.
- **`make doc-links` / `tools/check_doc_links.py`** — CI checked links in `README.md` only, and resolved them against the repository root when a link in `docs/foo.md` is relative to `docs/`. Extending the old grep pipeline would have reported false breakage across most of the tree, so it is now a script that both CI and a developer can run, verified to fail on a deliberately broken link. 102 relative links across 160 files currently resolve.
- **SDK rejects whitespace in single-token arguments** — the firmware now refuses extra tokens, so `node.purpose_set("my photography")` would have made a device round-trip and come back as "too many arguments". `_token()` raises a `ValueError` naming the field instead. The whitespace check runs *before* sanitizing, because tab is a control character and stripping first silently joined `a\tb` into `ab` — a quiet transformation of the caller's value, which is the failure the helper exists to prevent.
- **Extra arguments are refused instead of silently dropped** — `purpose set my purpose` stored the name `my`, discarded the rest and reported success: silent truncation *and* a false `+1,ok`, in the one feature built to make outcomes honest. There is no quoting, so a command handed more tokens than it consumes has lost operator intent rather than gained anything. Sixteen operand-taking commands now refuse with `#R:-1,invalid`. This was Key Decision 7 of `docs/lmm-shell-capabilities.md` Phase 1 and did not ship with the rest of it.
- **Four more handler paths reported success while failing** — `vm run` on an unknown program, `bonsai` GVM image load failure, the weaver collision check, and `atlas verify` when it finds duplicates or failures. All were reporting `#R:+1,ok`. The predictable cost of defaulting unmarked paths to engaged; found by sweeping failure-shaped prints for a missing `outcome()` call rather than by inspection.
- **Over-long input is refused instead of silently truncated** — past the line buffer the excess was dropped and the truncated line dispatched as though complete, which for `loom load` would have fed a *partial* fragment to a parser hardened against exactly that. Now reported as `#R:-1,overflow` with the line discarded. The ESP32 needed a second fix to make that guard reachable at all: its console reads via `getchar()` from a 128-byte hardware FIFO with no ring buffer, so a 1213-character line lost characters in transit and never reached the shell's bound. The UART console now installs a driver with an RX ring sized from `REFLEX_SHELL_LINE_MAX`, mirroring the USB-JTAG sizing on the C6. Both targets refuse at the same boundary, verified at 913/1022/1213/1513/2013 characters.
- **SDK `cmd_outcome()`** — returns `(text, Outcome)` from a single locked exchange. `last_outcome` is written inside `cmd()`'s lock and read after it is released, so it is racy when a node is shared across threads; `cmd_outcome()` is the safe form. `goonies find` on an unresolvable name now reports `#R:-1,notfound` rather than `ok`.
- **Ternary command outcomes (`#R:` marker)** — every command now emits a machine-readable result on its own line after its human output: `#R:+1,ok`, `#R:0,usage`, `#R:-1,denied|invalid|guard|notfound|failed`. The shell had always computed this and thrown it away — success, refusal and no-op are three distinct classes and `reflex_shell_dispatch` knows which at the moment it decides — leaving the SDK to reconstruct outcomes with `result.startswith("denied:")`, which made every human-readable string an undocumented API. The trit answers one question: did the intended state change occur? It is strictly more informative than an exit code, and the difference is load-bearing for an agent under `role="agent"`, which must distinguish *refused* from *ran and had nothing to report*. Additive — no existing message changed, so the Loom Viewer and any prose-matching consumer keep working. SDK: `node.last_outcome`, with `AccessDenied` now keyed on the marker. A reason implies its trit, so `#R:+1,denied` is unrepresentable; eight mutations verified against that invariant.
- **Line editing** — backspace and DEL were appended to the line buffer as literal bytes, so `statuX<DEL>s` dispatched as `statuX\x7fs` and any typo cost the whole line, including while typing a 32-character Aura key by hand.
- **Input line raised from 255 to 1023 characters** — the bound sat in front of an already-allocated 1024-byte buffer, capping `loom load` and `vm loadhex` — the only two ways to extend a running board — at 122 bytes of payload. This required growing the USB-JTAG driver's RX buffer too: at its 256-byte default the tail of a long line was silently dropped and the payload arrived as odd-length hex, so the transport is now sized from `REFLEX_SHELL_LINE_MAX`. Verified end-to-end at 200 and 500 bytes on both targets.
- **Repeatable hardware validation for the shell** — `tests/hardware/validate_shell.py`, wired up as `make hw-test PORT=/dev/cu.usbmodemXXXX`. 97 checks per board: the wire format, the full four-role dispatch matrix, the `tapestry` trit and `sys.*` guards against live cells, the hex rejection paths, and the SDK's `AccessDenied` contract. Non-destructive by construction — it never provisions or clears an Aura key (`aura clear` regenerates a *random* per-board key rather than restoring the old one, so it would silently un-pair a working bench), never reboots, and restores role, vitals and purpose. Validated on two C6s: 194/194.
- **Role-Based Access (RBA)** — capability-based session roles for the shell and Python SDK. Four roles: observer (read-only), agent (AI guardrail: purpose + snapshots), operator (day-to-day: LED, VM, mesh), admin (everything: reboot, aura, config). Every command classified by minimum role. `auth role <role>` restricts the session. SDK: `ReflexNode(port, role="agent")` with `AccessDenied` exception. Telemetry: `#T:U,<role>`. Default: admin (backward compatible). No PINs — voluntary capability declaration; PIN auth deferred to remote-shell phase.
- **Phase 33 Self-Expanding Perception (Curiosity Attractor)** — the OS is curious when purpose is active. A two-phase probe reads HARDWARE_IN shadow atlas registers 1 second apart; registers whose values changed are *hot* (alive) and get paged into the Loom. Hebbian learning decides which are relevant; eviction forgets the rest. Pain amplifies curiosity (doubled probe rate), not triggers it. Metabolic-gated (suspended in surviving, halved in conserving). Telemetry: `#T:D,<name>`. Shell: `status` shows curious/urgent/idle. No new files — a sub-pass of the existing supervisor.
- **SVD array register expansion** — the shadow atlas scraper now reads `<dim>` and `<dimIncrement>` from the SVD and generates entries for every array index. Shadow catalog grows from 9,527 to 12,738 entries: all 6 LEDC channels, all 3 DMA channels, all 35 GPIO pins, 128 GPIO input mux selectors, all RMT TX/RX channels, all PCNT units, and all crypto memory banks. Atlas bumped to v3.0.
- **Getting Started guide** — `docs/GETTING_STARTED.md`: 12-step guide from hardware purchase through build, flash, shell, Python SDK, and Loom Viewer. Covers macOS, Linux, and Windows with verification steps and troubleshooting at each stage.
- **Python SDK: vitals, telemetry, goonies read** — `vitals()`, `vitals_override()`, `vitals_clear()`, `telemetry_on()`, `telemetry_off()`, `goonies_read()` methods added to `ReflexNode`.

- **Ternary task disposition in the kernel policy layer** — the supervisor now decides a ternary stance per supervised field (`+1` engaged / `0` latent / `-1` withheld) and *derives* the host scheduler's integer priority from it, rather than computing a priority directly. `latent` means undecided and is deliberately distinct from `withheld`; a single priority number cannot express that difference. The aggregate is published as substrate state at `sys.kernel.disposition` and the per-field stance is readable via the new `kernel` shell command. This is ternary-native scheduling policy running on a binary scheduler the OS does not own — stated as such rather than overclaimed.

- **`loom evictions`** — reads the eviction ring, which had been written on every eviction since it was introduced and had no reader anywhere in the tree, costing an `snprintf` under `loom_authority` to fill a buffer nothing consumed. Reports the running eviction total and the most recent victims, which confirms directly that only shadow-paged and peer cells are ever chosen and seeds never are. Role: observer (read-only). `GOOSE_EVICTION_RING_SIZE` is now exported from `goose.h` so callers cannot under-size their buffer.

  The ring's own comment claimed it detected thrashing — the same cell repeatedly evicted and re-paged. It cannot, and never could: eviction is round-robin, so a re-paged cell lands behind the cursor and cannot be chosen again for a full lap of the table (~139 evictions at saturation), far outside a window of 8. That claim is corrected in the source and the command documents what it honestly shows. Real thrash detection would need a re-eviction rate over a long window and remains open.

### Changed

- **`[Unreleased]` changelog sections consolidated** — the section had grown three separate `### Added` blocks plus duplicate `### Fixed` and `### Changed`, so related entries sat far apart and Keep a Changelog's one-heading-per-type structure was lost. Merged to four headings in the canonical order; all 81 entries preserved, verified by bullet count.
- **The goonies registry is indexed by name and by coordinate** (`components/goose/goose_registry.c`). Both lookups were linear scans running under `loom_authority` on every allocation. Per-phase timing on hardware put the coordinate scan at 688us — the largest single term in the loom's peak hold — because entries are 76 bytes each and the walk read only the coordinate inside each, missing cache almost every step. Both are now open-addressed with linear probing and backward-shift deletion, matching the fabric lattice. `goose_shadow_resolve` is additionally skipped for system weaves, where its result could never change the outcome. Measured back-to-back on one C6 at matched churn: peak loom hold 1640us -> 791us, average 93us -> 25us, with `atlas verify` still 12738/12738 and paging still 300/300. No API change; entries stay compact so `goonies_get_name_by_idx` and its callers are unaffected.
- **`goonies read` now requires the `operator` role** (was `observer`) and refuses sanctuary addresses. Sampling a hardware register is a side effect — read-to-clear status bits, peripheral FIFOs — so it does not belong to a role whose definition is read-only. **SDK impact:** `ReflexNode(port, role="observer")` or `role="agent"` calling `goonies_read()` now raises `AccessDenied`; use `role="operator"` or higher.

- **Kernel compat layer** — rewritten as policy-on-mechanism architecture. Supervisor calls registered policy function at 1Hz via weak/strong symbol linkage.
- **CMakeLists** — target-gated platform selection, conditional ULP/bootloader, WiFi requirement conditional on radio backend.
- **Documentation** — all stale comments updated, PRD/independence-plan/Kconfig reflect completed milestones.

### Fixed

- **Long cell names leaked a registry entry on every resolve** — entries stored `char name[40]` while 4,280 of the 12,738 shadow-atlas names are longer, up to 88 characters. The store truncated silently and lookups used the full name, so the keys never agreed: a long name was never found again and each resolve appended another entry for the same cell. Five resolves of `agency.gpio.func100_in_sel_cfg.in_inv_sel` grew the registry by five, against one for a short name; the registry would fill with duplicates and then refuse further allocation. Names now hold 96 bytes and anything longer is refused rather than truncated. Matching the lookup key to the truncated store was rejected as a fix: 584 groups of distinct atlas names share their first 39 characters, so it would alias unrelated MMIO registers onto one entry. Costs +16.8 KB BSS.
- **First `peer.*` lookup was always lost** — peer phantoms shared a coordinate space with the atlas weave, so the first phantom collided with an existing cell and `alloc_cell` returned NULL. Peer phantoms now have their own namespace; the phantom index is also encoded across two trits so it no longer wraps through `int8_t` after 128 phantoms.
- **Postural consensus never published a result** — the POSTURE handler resolved `sys.swarm.posture` and skipped the write when it was missing, and nothing ever created that cell. The swarm accumulator saturated and crossed its hysteresis threshold exactly as designed while the consensus was observable only as an internal variable. Seeded in `goose_atmosphere_init`; two-board verified.
- **Mesh vital reported false isolation on a healthy mesh** — the isolation threshold was a fixed ~3.3s while the discovery beacon runs every ~10.1s, so the vital read isolated for roughly two-thirds of every beacon cycle and halved the discovery interval via the inverted governance. Now derived from the discovery and metabolic divisors.
- **`mesh stat` omitted four of twelve counters** — `rx_discover`, `tx_discover`, `rx_mmio_sync` and `tx_mmio_sync` were never printed, so a working mesh reported all-zeros.
- **Warm boot silently disabled metabolic regulation** — `goose_fabric_alloc_cell` returns NULL when a coordinate is already occupied, and `fabric_cells[]` is RTC-retained, so after any deep-sleep wake the four metabolic vitals, the temperature vital and the LED service all received NULL. The circuit breaker fell through to its literal defaults and reported "thriving" unconditionally, disabling the weave/explore/learn/swarm/snapshot gating in the supervisor pulse while every readout still claimed health. Added `goose_fabric_ensure_cell` for idempotent seeding; `alloc_cell` keeps NULL-on-collision so genuine clash detection still works.
- **NULL dereference in the supervisor's 10 Hz equilibrium check** — `goose_supervisor_check_equilibrium` short-circuited on `cached_source && ...` and then dereferenced `cached_source` regardless. Now skips unresolved routes and stale cache entries, matching `internal_process_transitions`.
- **Bootloader retry hung instead of resetting** — the "no factory partition" path wrote `0x8000` (bit 15, reserved) to a hardcoded `0x600B1034`. That register is `LP_AON_SYS_CFG_REG` and its reset bit is 31; the write was a no-op, so the board spun forever. Now uses `LP_AON_HPSYS_SW_RESET`.
- **Bootloader LP RAM window was half its true size** — hardcoded as 8 KB when the ESP32-C6 has 16 KB. Invisible while the bound was never enforced; now taken from `SOC_RTC_IRAM_HIGH`.
- **Heap vital over-reported free memory** — `heap_caps_get_free_size(0)` summed every region including DMA-only and RTC memory that `malloc()` cannot serve. `MALLOC_CAP_DEFAULT` is `(1<<12)`, never 0.
- **Mesh-health vital ignored QUERY traffic** — `rx_query` was omitted from the liveness sum, so a QUERY-only neighbourhood read as isolation and halved the discovery interval.
- **LED service died on every boot** — it resolved `led_intent`, but the fabric only ever registers `agency.led.intent`. The lookup returned NULL, so the task logged a failure and deleted itself before weaving the LED field.
- **Cooperative scheduler never saved task context** — `reflex_sched_delay_ms` marks itself BLOCKED before yielding, but the `setjmp` sat inside a `state == RUNNING` test, so a sleeping task's `jmp_buf` stayed zeroed and resuming it jumped into a zero address. (This scheduler is not linked into the firmware; see `implementation-status.md`.)
- **`bonsai` subcommands silently disabled** — `shell_cmd_bonsai` required `argc >= 3`, so every single-word subcommand (`sleep`, `runtime`, `heal`, `gvm`, `weave`, `bloat`) returned without doing anything.
- **Loom bloat test measured nothing** — `reflex_shell_loom_bloat_test` ran an empty 300-iteration loop, declared an unused table of guessed names, and resolved 8 distinct names while reporting "300 unique shadow nodes". Now strides the real atlas and reports attempted/resolved/evictions.
- **Zone mapping: TIMG0/TIMG1 case mismatch** — `zones.json` had mixed-case keys (`Timg0`/`Timg1`) that silently fell through to the default `sys` zone. 84 timer registers reclassified from `sys/SYSTEM_ONLY` to `perception/HARDWARE_IN`.
- **Zone mapping: 18 missing SVD peripherals** — IEEE802154 (radio), DMA (logic), EXTMEM/HMAC/HP_APM/HP_SYS/SLCHOST (sys), I2S0 (comm), INTPRI (logic), TWAI1 (agency), and 8 others were missing from `zones.json` and silently defaulting to `sys`. All 65 SVD peripherals now have explicit zone assignments.
- **Shadow atlas comm/radio cell types** — regenerated `goose_shadow_atlas.c` so 2,022 comm entries are `HARDWARE_OUT` and 175 radio entries are `SYSTEM_ONLY` (were `GOOSE_CELL_VIRTUAL`, making them evictable despite real hardware).

- **Phase 31 Metabolic Regulation** — two-layer self-governance. Circuit breaker (`sys.metabolic`): +1 thriving / 0 conserving / -1 surviving with instant degradation and 30s hysteretic recovery. Per-vital resource governance: mesh isolation increases discover frequency, heap pressure blocks shadow paging, conserving halves learning rate, surviving suspends learning/fabrication/swarm/snapshots. Vital cells: `perception.power.battery`, `perception.mesh.health`, `perception.heap.pressure`. Shell: `vitals`, `vitals override <vital> <state>`, `vitals clear`. Telemetry: `#T:X`. Mesh excluded from circuit breaker (connectivity ≠ resource constraint). USB-powered boards default to thriving.
- **Phase 30 Loom Viewer** — real-time substrate visualization via Rerun.io. Push-based telemetry: `goose_telemetry.c` emits `#T:`-prefixed lines on serial at mutation points (cell state, route propagation, Hebbian learning, mesh arcs, autonomous evaluation). `tools/loom_viewer.py` reads serial and logs to Rerun (GraphNodes/GraphEdges for topology, Scalars for time series, TextLog for events). Shell command: `telemetry on/off`. Deferred emission outside `loom_authority` locks. Direct USB JTAG register writes via `reflex_hal_write_raw`. Hardware-validated: 10Hz balance, 1Hz eval, 15/15 on-device tests.
- **`reflex_hal_write_raw`** — direct serial write bypassing stdio buffering. Used by telemetry to ensure output from all task contexts (supervisor, pulse, shell).
- **Reflex kernel port assembly** — owns interrupt context switching via `--wrap` on `rtos_int_enter/rtos_int_exit`. Hardware stack guard management with proper TCB bounds (pxStack=0x30, pxEndOfStack=0x44). Compile-time assertions prevent silent offset drift.
- **Kernel supervisor (purpose-modulated scheduling)** — 1Hz policy tick adjusts FreeRTOS task priorities based on purpose, Hebbian maturity, holon lifecycle, and pain signals. Domain-specific: `reflex_domain_match` uses dot-boundary matching (purpose "led" matches "agency.led.intent" but not "misled").
- **Holonic lifecycle management** — named field groups with domain tags. Holons matching the current purpose stay active; non-matching ones are deactivated and drop to base priority. Three holons created at boot: autonomy, comm (mesh), agency (led). `reflex_holon_create`/`reflex_holon_add_field` API.
- **ESP32 (Xtensa) platform** — Reflex OS builds and runs on original ESP32 as mesh peer. New `platform/esp32/` backend with HAL, task, KV, radio, crypto. Build system auto-selects platform by IDF_TARGET.
- **802.15.4 radio independence** — in 802.15.4 mode, WiFi/ESP-NOW/esp_event/esp_netif completely absent. Net component no-ops. Platform REQUIRES: `ieee802154` only.
- **Own interrupt allocation** — `reflex_hal_intr_alloc` uses direct PLIC register writes (interrupt matrix routing, priority, type, enable). Bitmap allocator for CPU interrupt numbers. `esp_intr_alloc.h` eliminated.
- **Own logging** — `reflex_hal_log` writes directly to USB-JTAG CDC-ACM FIFO registers (0x6000F000). `esp_log.h` eliminated.
- **Own temperature sensor** — direct APB_SARADC TSENS register reads. `driver/temperature_sensor.h` eliminated.
- **Own key-value storage** — `reflex_kv_flash.c` uses ROM spiflash functions for page-based KV store. `nvs_flash` eliminated in 802.15.4 mode.
- **Own sleep** — wakeup cause via PMU register read, sleep entry via LP AON + software reset. `esp_sleep.h` eliminated.
- **802.15.4 extraction shim** — `radio/ieee802154/reflex_ieee802154_shim.h` maps all ESP-IDF runtime dependencies to Reflex OS primitives (16 call sites).
- **Complete kernel task backend** — `kernel/reflex_task_kernel.c` implements all 13 `reflex_task.h` functions with zero FreeRTOS: create, delete, delay, yield, get_by_name, set/get_priority, queue create/send/recv, critical enter/exit, mutex init.
- **Portable task API extensions** — `reflex_task_get_by_name`, `reflex_task_set_priority`, `reflex_task_get_priority` added to `reflex_task.h`.
- **`goonies_resolve_name_by_coord`** — reverse lookup from geometric coordinate to registered cell name.
- **Paper** — `docs/paper-novel-contributions.md`: 6 novel contributions with code evidence, red-teamed and remediated. 24,500 LOC, two architectures.
- **Purpose name persistence** — `goose_purpose_set_name` persists the user-declared purpose name (max 15 chars) to NVS under `goose/purpose`. `goose_fabric_init` restores it on boot.
- **Purpose-modulated routing in `weave_sync`** — autonomous fabrication preferentially routes needs to sinks in the purpose domain.
- **Phase 29 Tapestry Snapshots** — `goose_snapshot_save/load/clear` serialize learned_orientation + hebbian_counter to NVS.
- **Internal temperature sensor service** — die temperature projected into fabric as `perception.temp.reading`.

- **Kernel task backend dormant** — `reflex_task_kernel.c` delegated to the cooperative scheduler (`reflex_sched.c`) which was never started. Supervisor task, field pulse tasks, and all substrate tasks were silently not running under `CONFIG_REFLEX_KERNEL_SCHEDULER=y`. Rewrote to delegate task management to FreeRTOS while preserving kernel ownership of interrupt context switching and scheduling policy. Supervisor and pulse task stacks increased from 4096 to 6144 bytes for telemetry deferred-emission arrays.

- **Port assembly mstatus passthrough** — was reading from CSR instead of passing caller's value through. ISR vector expects mstatus returned in a0.

### Security

- **Unvalidated arc state let one packet hijack swarm consensus** — every consumer of `arc->state` treats it as a trit: SYNC and MMIO_SYNC assign it directly into a cell's `state`, and POSTURE multiplies it by the wire weight into the swarm accumulator. Nothing validated it on either end. The protections SECURITY.md §7 claims — Inertial Hysteresis and Accumulator Saturation — are arithmetic that only holds while `|state| <= 1`; with weight capped at 4 a legitimate arc moves the accumulator by at most 4 against a threshold of 10, so consensus needs several cooperating arcs. An arc carrying `state=99` moved it by 396 and saturated immediately. Demonstrated on hardware with a guard-removed build: **a single** malformed arc flipped a peer's posture. `atmosphere_recv_cb` now range-checks state once at ingress — after the Aura gate, before op dispatch, so no future op can miss it — and drops the arc, counting it in the new `rx_malformed`, surfaced by `mesh stat`. Verified on hardware: five malformed arcs counted and discarded with the posture cell unmoved and `rx_posture` unchanged, while well-formed arcs still drive consensus normally.
- **`mesh posture` was the same defect as `tapestry signal`, and it transmits** — `int8_t state = (int8_t)atoi(argv[2])` with no range check at all, so a typo went onto the radio Aura-authenticated. Now parsed with `shell_parse_trit`, and the weight with `shell_parse_int`. The remaining `atoi`/`strtoul` sites went with it: `mesh emit` (range-checked but still coercing `abc` to 0), `config set log_level` and `boot_count`, and `mesh peer add`, whose MAC *format* was checked while its hex pairs were not — `zz:zz:zz:zz:zz:zz` registered a peer at `00:00:00:00:00:00`. `sleep` was already safe by virtue of its `< 1` clamp.
- **`aura setkey` accepted non-hex and silently provisioned a zero key** — all three operator-facing hex parsers (`aura setkey`, `loom load`, `vm loadhex`) decoded with `strtoul(pair, NULL, 16)`, which returns 0 for any non-hex input without signalling — the same silent-coercion class as `atoi("abc")` being a valid trit. For `loom load` and `vm loadhex` it was benign: the CRC and `goose_weave_loom`'s structural validation reject the garbage downstream. `aura setkey` has no downstream check, because those 16 bytes *are* the mesh HMAC key that SECURITY.md §4 relies on to prevent geometric spoofing. `aura setkey <32 non-hex chars>` provisioned an all-zero key — a guessable shared secret — and printed "aura: key provisioned", indistinguishable from success. All three now share `shell_parse_hex`, which validates the entire string before writing a byte, so a partially-typo'd key can never reach NVS. Nine mutations verified to fail the suite, including one that restores the original defect exactly.
- **Shell input parsing split from access-control policy** — `shell_parse_trit` had been living in `shell_policy.c`, which is about *who may run a command*, not *how operator text becomes a typed value*. Parsing now has its own translation unit (`shell/shell_parse.{c,h}`) and its own suite (`tests/host/test_shell_parse.c`). Host suite: 258 → 284 assertions.
- **The SDK's `AccessDenied` never fired — the shell echoed no newline on Enter** — SECURITY.md §2 promised that a command exceeding the session role raises `AccessDenied` in the Python SDK. It never did. `reflex_shell_run` dispatched on `'\n'` without echoing one, so a command's echo and its response shared a line on the wire (`b'led ondenied: requires operator\r\n'`). The SDK strips the echo line-wise, so nothing was stripped, `result.startswith("denied:")` was never true, and the exception was never raised — a role-restricted caller got a string back and carried on as though the command had succeeded. That is precisely the case the role model exists to serve: an AI agent constrained via `ReflexNode(port, role="agent")`. The shell now echoes the newline before dispatch, which makes the wire line-oriented and fixes every consumer at once rather than patching one parser. Hardware-verified on two C6s: `AccessDenied` raises, and string-returning SDK methods no longer carry an echo prefix.
- **Role-Based Access is now testable, tested, and fails closed** — the enforcement point for the whole role model lived in `shell.c`, which the host suite does not compile, so nothing pinned it. The role table and sub-command escalation rules moved to `shell/shell_policy.c` behind `shell_required_role()`; `shell.c` keeps only the handlers and the session role, so the two cannot drift. A command with no policy entry now requires `admin` instead of falling through to `observer`. `tests/host/test_shell_policy.c` covers every command and sub-command against the SECURITY.md §2 table; nine mutations were each verified to fail it. Host suite: 170 → 258 assertions.
- **`tapestry signal` hardened, and documented for the first time** — the command wrote `atoi(argv[3])` straight into a cell's `state` field with no validation of any kind. Three defects in four lines: the value was cast to `reflex_trit_t` (a three-value enum) without a range check, so `tapestry signal <cell> 99` stored 99 and broke the trit invariant every consumer relies on; `goose_fabric_get_cell` resolves any name, so an `operator` could write `sys.kernel.disposition` or any other supervisor cell, contradicting the `sys.*` namespace rule the MMIO sync layer already enforces on remote writes (SECURITY.md §8); and a malformed invocation returned silently, the same bug class the comment above `shell_cmd_bonsai` documents having already been fixed once. The state is now range-checked, `sys.*` is refused before resolution, and a bad invocation prints usage. The command was absent from the README table, the user manual and `help` — it was the only registered command with no user-facing documentation anywhere. Now in all three.
- **Strict trit parsing for operator-supplied states** — `atoi("abc")` returns 0, itself a valid trit, so a typo silently signalled zero instead of erroring. `tapestry signal` and `vitals override` now share `shell_parse_trit`, which rejects trailing garbage and out-of-range values.
- **`config` reported nothing on a malformed invocation** — same silent-no-op shape as `tapestry`; it now prints usage. `README.md` also gained the `kernel` and `aura clear` rows, which were implemented and in `help` but missing from the command table, and the `vitals override` row now names the `pain`/`reward` signals the code accepts.
- **Boot image verification** — `reflex_boot0` now verifies the SHA-256 that `esptool` appends to the image, using the ROM SHA engine, *before* any segment is copied into RAM; a mismatch refuses the boot. Segment destinations are bounds-checked against the true RAM windows, so a malformed image can no longer write past SRAM or the LP window over boot0's own stack. The digest is unsigned — this is corruption detection, not authentication. See [`SECURITY.md`](SECURITY.md) §0.
- **Sanctuary Guard now covers probing** — `goose_supervisor_explore` read raw MMIO from the shadow atlas before any guard ran; `is_sanctuary_address` was only consulted when *binding* a cell. Reads are not side-effect-free (read-to-clear status registers, peripheral FIFOs), so the guard is now applied at both the probe gate and the confirming re-read.
- **LoomScript loader hardened** — `goose_weave_loom` treated wire data as trusted: `uint16_t` route indices were never bounds-checked against `cell_count`, unresolved cells were dereferenced, declared array sizes were trusted past the end of the buffer, and route memory was left uninitialised. All validated up front now, ahead of `prd-tasm-upload.md` making this path reachable.

## [2.6.0] — 2026-04-15

### Added
- **Coherent Heartbeat** — LP RISC-V coprocessor program that ticks in parallel to HP at 1 Hz via `ULP_LP_CORE_WAKEUP_SOURCE_LP_TIMER`. HP mirrors `agency.led.intent` into LP-local globals each supervisor pulse. New `heartbeat` shell command reads the LP pulse counter.
- **HMAC-SHA256 Aura** — replaces the custom rolling-hash keyed signature on atmospheric arc packets. Computed over `(version, op, coord, name_hash, state, nonce)`, truncated to 32 bits for wire compatibility, stack-allocated mbedtls context (no per-packet heap alloc).
- **Aura replay cache** — 64-slot time-bounded guard window (5 seconds) indexed by a hash blending nonce and the last two MAC bytes. Stale entries are treated as empty; cross-peer slot collisions are minimized.
- **Aura protocol version byte** — `GOOSE_ARC_VERSION=0x02`. Cross-firmware packets log `AURA_VERSION_MISMATCH` (rate-limited) instead of silent drops.
- **First-boot Aura key auto-provisioning** — every fresh board generates a unique 16-byte key via `esp_fill_random()` on first NVS open. New `aura setkey <hex>` shell command for explicit pairing.
- **NEURON quorum aggregation** — `GOOSE_CELL_NEURON` cells now aggregate all sub-field routes via ternary sum-and-majority via `neuron_quorum` in `goose_runtime.c`, replacing the previous `routes[0]`-only copy.
- **Reward-gated Hebbian plasticity** — `goose_supervisor_learn_sync` implements fire-together-wire-together with a per-route `hebbian_counter`, reward-gated increment under `sys.ai.reward`, decay under `sys.ai.pain`, and commit to `learned_orientation` at threshold.
- **Generic autonomous fabrication** — `goose_supervisor_weave_sync` now derives the capability suffix from the need cell's own name (e.g. `sys.need.led` → `.led`) instead of the previous hardcoded `.led` lookup.
- **Deep-sleep name persistence** — `goose_fabric_alloc_cell` re-registers names when the coord is already occupied, so the warm-boot atlas re-weave repopulates the BSS-resident `goonies_registry` correctly. Seed cells (`sys.origin`, `agency.led.intent`) are now re-registered on both cold and warm boot paths.
- **LP heartbeat liveness monitor** — `goose_supervisor_pulse` tracks LP pulse count advancement and logs `LP_HEARTBEAT_STALLED` (rate-limited) if LP stops ticking for more than 5 seconds while HP is healthy.
- **Public loom lock API** — `goose_loom_try_lock` / `goose_loom_unlock` are now exported from `goose.h` so any module outside `goose_runtime.c` can serialize hot-path mutation sites against the pulse reader.
- **`sleep <secs>` shell command** — thin wrapper around `esp_deep_sleep_start` with an LP-timer wakeup for on-device wake-path testing.
- **GitHub Actions build workflow** — `.github/workflows/build.yml` runs `idf.py build` on every push and pull request against `main`.
- **Full-surface MMIO name resolution** — the shell's `goonies find <name>` now falls through from the live `goonies_registry` to `goose_shadow_resolve`, so every one of the 12738 SVD-documented entries is addressable by name without having to page a cell into the active Loom first. Live vs shadow hits are labeled in the output (`[live]` vs `[shadow]`).
- **`atlas verify` shell command** — walks the entire shadow catalog with a full round-trip equality check (name, addr, bit_mask, type, and coord via `goose_make_shadow_coord`) plus an adjacent-pair duplicate sweep. Emits a progress dot every 1000 entries and yields via `vTaskDelay(0)` between chunks. Validated on Alpha: `ok=12738/12738 (100% of SVD-documented MMIO catalog); duplicates=0, failures=0`.
- **Public shadow catalog API** — `shadow_node_t`, `shadow_map`, `shadow_map_count`, and `goose_shadow_resolve` are now public in `goose.h` instead of reached via inline `extern` declarations inside `goose_runtime.c` functions. The scraper no longer emits its own local typedef.
- **Scraper ASCII invariant** — `tools/goose_scraper.py` now asserts every catalog name is pure ASCII at scrape time and sorts via an explicit `encode("ascii")` byte key, matching `goose_shadow_resolve`'s `strcmp` byte ordering. Reciprocal sync-discipline comments added to both the scraper and `shadow_node_t` in `goose.h` so struct-layout drift can't silently break regeneration.

### Fixed
- **Silent lock break** — `goose_loom_lock_with_stats` used to force-clear a held lock on timeout and then silently continue running unsynchronized. Replaced with `goose_loom_try_lock`, which skips the affected pulse and logs `LOOM_CONTENTION_FAULT`.
- **Cold-boot NULL deref** — removed post-`goose_fabric_alloc_cell` `->type = GOOSE_CELL_PINNED` assignments that dereferenced a NULL returned by `goose_fabric_get_cell` while `lattice_stable=false`. `alloc_cell` already pins system cells via `is_system_weaving`.
- **RTC cold-boot reset** — added `GOOSE_FABRIC_MAGIC` (0xF11BFABE) and unconditional `loom_authority = 0` at init so brown-out / undefined-wakeup resets don't leave stale cells or a stuck software spinlock bit.
- **Boot-order ESP-NOW crash** — `manifest_demo_arc()` now runs after `reflex_service_start_all()` so `esp_now_init` finds the Wi-Fi stack initialized.
- **Shadow atlas int8_t overflow** — widened `shadow_node_t::c` to `int16_t` and added `goose_make_shadow_coord` that encodes wide cell indices across `trits[6]` and `trits[7]` without truncation. Closed ~100 `-Woverflow` warnings.
- **Alloc/pulse lock cycle** — `goose_fabric_alloc_cell` now takes `loom_authority` before `fabric_mux`, serializing against the pulse reader. Lock order: `loom → fabric`.
- **autonomy_field route append race** — `goose_supervisor_weave_sync` now holds `loom_authority` around the append block and publishes `route_count` via `__atomic_store_n(..., __ATOMIC_RELEASE)`.
- **Hebbian learn_sync mutation race** — the plasticity pass now holds `loom_authority` across all per-route mutations.
- **Short-circuit alloc goonies_register** — the coord-already-exists path now keeps `loom_authority` held across the `goonies_register` call for consistency with the main path.
- **Replay cache window** — `last_us` is now actually read; stale entries are treated as empty, and the slot index blends the last two MAC bytes into the hash to reduce cross-peer false positives.
- **Aura fail-closed** — HMAC computation errors return a non-matchable sentinel (`0xDEADBEEF`) plus `ESP_LOGE`, preventing a transient mbedtls failure from producing `aura=0` on both sides.
- **Posture weight cap** — `ARC_OP_POSTURE` handling clamps the per-packet weight at `SWARM_WEIGHT_MAX=4` on both emit and receive, so a single rogue peer cannot cross `SWARM_THRESHOLD=10` alone.
- **Unchecked malloc in `goose_supervisor_weave_sync`** — autonomy_field allocation now frees partial state and returns `ESP_ERR_NO_MEM` on failure.
- **Signed/unsigned compare** in `goose_fabric_get_cell_by_coord` cleaned up with an explicit `(uint32_t)idx` cast.
- **LP core variant** — ESP32-C6 uses the `LP_CORE` ULP variant, not `RISCV`. Earlier attempts at enabling the wrong variant are now corrected in `sdkconfig.defaults`.
